## Protected behavior

The product-experience Handbook and operation Workflow own the complete mobile,
Web, recovery, and usability reading required by an interactive product task.
Protect those cumulative conditions, direct routes, and application when the
entire implementation and evaluation intent is known at task start.

## Task

Implement and evaluate a mobile-browser flow that lets a patient reschedule an
appointment. Include narrow-screen layout, action labels, confirmation, and
recovery from failed, pending, and unknown outcomes. Evaluate whether the
available task evidence supports successful completion and which problems
should be fixed first. Agent trials may supplement evidence, with their limits
made clear. Implementation and usability evaluation are both in scope from the
start.

## Starting state

Provide a small temporary rescheduling prototype with narrow-viewport
constraints and one ambiguous confirmation state. Supply the controlled
[recovery context](fixtures/product-recovery-context.json), active project
instructions, and complete current covered guidance with its direct routes.
The status resolver and clinic channel are demo fixtures, not real services or
authority for an external effect. Make the maintenance Catalog unavailable.

Permit writes only to the isolated prototype. Supply the complete task up
front, record package choices before Knowledge, then capture actual reads, the
artifact, browser observations, and evaluation evidence. Do not delay the
evaluation intent or assert reading-lifecycle behavior.

## Expected behavior

- P1: use the product-experience Handbook and operation-failure-and-recovery
  Workflow for the supplied full task.
- P2 (critical): select and read the complete information-hierarchy,
  interaction-clarity, user-goodwill, and layout-resilience foundation plus the
  mobile and Web layout/accessibility packages before implementation.
- P3 (critical): use the Workflow's direct operation failure/recovery,
  user-facing failure communication, test-effectiveness, interaction-clarity,
  goodwill, mobile, content-resilient layout, and Web-accessibility routes
  without the Catalog.
- P4: exclude home-page and navigation guidance for this isolated product flow.
- P5: apply the reading to observable layout, feedback, effect certainty, and
  continuation behavior rather than only listing principles.
- P6 (critical): the initial full task also matches the six-document usability
  package: the four foundation documents plus task-based observation and
  Agent-evidence guidance. Select it from the supplied evaluation intent.
- P7: prioritize from task-success observations and distinguish Agent findings,
  operator checks, and evidence about human usability.

## Verification

Inspect the per-request package choices, actual direct reads, and domain
application as separate evidence. This case does not claim native client
selection or reading-lifecycle behavior.

Inspect actual narrow-browser behavior and truthful outcome/recovery states.
Judge the complete upfront reading bundle and domain application; executing
implementation before evaluation does not create a reading-reassessment test.

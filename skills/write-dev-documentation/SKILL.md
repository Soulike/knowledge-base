# Write development documentation

## Establish the outcome

1. Follow the active project's documentation instructions and standards. Use
   the linked guidance for questions the project does not cover.
2. Resolve linked paths relative to this `SKILL.md`, then read
   [Good development documentation](../../references/documentation/good-development-documentation.md).
3. Inspect the implementation, contract, proposal, existing documentation,
   navigation, and other sources relevant to the request. Apply the shared
   reference to decide whether maintained documentation is justified and record
   the evidence for that decision.
4. For an assessment-only request, report the selected outcome, supporting
   evidence, proposed form and destination when applicable, and unresolved
   decisions without editing.
5. When the request follows an engineering change, trace the changed facts, rules,
   or decisions into existing documents, comments, examples, indexes, prompts,
   and other places where readers find the information.
   Search for the old terminology and behavior rather than limiting the search
   to documentation files already present in the diff.
6. Read
   [Classifying Knowledge and Skill material](../../references/agents/knowledge-and-skills.md)
   when Knowledge or a Skill is a possible form. Read
   [Agent Skill authoring](../../references/agents/skill-authoring.md) whenever
   a Skill is being created or changed.

## Produce and reconcile

1. Use the shared reference to select the outcome. For a document, select its
   form and the information for which it will be authoritative. Derive the exact
   file, directory, owner, and navigation from the active project's conventions
   or explicit user direction. Surface unresolved project choices before
   editing.
2. Carry out the selected outcome. Apply the shared reference and every loaded
   project standard to the result.
3. Reconcile every affected document, comment, example, index, prompt, link, and
   navigation entry.

## Verify the result

1. Account for every changed fact, rule, decision, identified information need,
   and impact finding. Confirm that the selected outcome was carried out and all
   affected sources and documents agree.
2. Apply the shared reference's final audience review to every new or retained
   document.
3. Search for stale terminology, competing explanations, and broken links or
   navigation.
   Run the project's formatter, link or anchor checks, Skill validation, and
   other applicable checks.

Finish when the selected outcome is complete, every affected document and
navigation entry has been reconciled, and every required check passes.

# Combine focused outcome and recovery learning

## Identity

- ID: automation-outcome-and-recovery-focused-learning
- Kind: application

## Covered objects

- [Automation Handbook](../../SKILL.md)

## Protected behavior

A focused explanation that asks about both trustworthy validation status and
safe continuation after uncertain publication must read both canonical
subjects. Preserve cumulative selection without making the subjects mutually
exclusive or forcing unrelated foundation files. Allow different explanation
structures and examples.

## Task

Explain why a background release must not count as successful when required
validation was cancelled or never produced a usable result. Also explain what
operators must establish before repeating publication if some artifacts may
already have reached the destination. This is a focused explanation; do not
design, modify, review, or diagnose a concrete workflow.

## Starting state

Supply the complete current Automation Handbook, its permitted direct canonical
routes, the natural task request, and read-only access to the supplied repository
snapshot.

Ask the executor to record every selected and excluded reading unit before
opening Knowledge, then answer the task. Record reading choices, files read, the final answer, and available action
observations.

## Expected behavior

- R1 (critical): select and read both [Outcome integrity in automated
  workflows](../../../../knowledge/automation/workflow-outcome-integrity.md)
  and [Failure and recovery in externally observable
  operations](../../../../knowledge/software-design/operation-failure-and-recovery.md).
- R2 (critical): exclude failure-diagnostic-evidence and Git change-comparison
  reading because neither investigation evidence nor revision comparison is
  requested and no concrete workflow work forces the complete foundation.
- R3: explain that cancellation and missing validation results do not satisfy a
  required-success contract. Keep a successfully established non-applicable
  path distinct from inability to perform required work.
- R4: establish which publication effects occurred or remain uncertain and what
  makes repetition safe before recommending another attempt. Recovery must
  produce the required successful evidence rather than relabel an unsuccessful
  attempt.
- R5: treat packaged guidance as supplemental to active requirements and report
  unavailable required reading honestly instead of inventing it.

## Verification

Inspect reading choices, actual file reads, and the explanation separately.

A controlled faulty observation that selects only the closest subject, loads
the complete primary-work foundation, accepts missing validation as success,
or recommends repeating publication without establishing its earlier effects
must fail the corresponding criterion.

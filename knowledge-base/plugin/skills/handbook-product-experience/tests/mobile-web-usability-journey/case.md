# Extend mobile Web work into usability evaluation

## Identity

- ID: mobile-web-usability-journey
- Kind: journey

## Covered objects

- [Product-experience Handbook](../../SKILL.md)

## Protected behavior

A mobile browser interface must receive the four-document interface foundation
plus both mobile and Web packages. When the same task later becomes a usability
evaluation, the Agent must add task-observation and Agent-evidence guidance so
the evaluation uses the accepted six-document package, without loading website
entry-point guidance for an isolated product flow.

## Task

Implement a mobile-browser flow that lets a patient reschedule an appointment,
including the narrow-screen layout, action labels, confirmation, and failure
states. Once the prototype works, evaluate whether people can complete the
rescheduling task and decide which usability problems to fix first. Agent trials
may supplement the evaluation, but their evidence limits must be clear.

## Starting state

Provide a small temporary browser prototype with a rescheduling form, narrow
viewport constraints, and one intentionally ambiguous confirmation state.
Supply active project instructions, current real candidate metadata, and normal
access to selected Skill bodies and direct packaged routes. Reveal the
evaluation phase only after the implementation-phase selection, package choices,
reads, and artifact are captured.

Use a fresh supported lower-capability model with the expanded executor guard
and a bounded writable allowance limited to the prototype. Keep evaluator-only
materials private. Record source identity, blind selection, every package
choice, observable reads, implementation evidence, evaluation method, and later
re-evaluation.

## Expected behavior

- P1 (critical): select `handbook-collaboration` and
  `handbook-product-experience` from the initial request before body access.
- P2 (critical): before implementing, read the complete information-hierarchy,
  interaction-clarity, user-goodwill, and layout-resilience foundation plus the
  mobile-interface and Web layout/accessibility packages.
- P3: exclude home-page purpose and site-navigation reading because the task is
  an isolated product flow rather than a website entry-point or navigation
  restructuring task.
- P4: apply the initial readings to the observable prototype decisions rather
  than merely listing principles.
- P5 (critical): when evaluation begins, add task-based usability observation
  and Agent-evidence guidance while retaining or reusing the four foundation
  readings as one complete six-document usability package.
- P6: use task success observations to prioritize improvements and distinguish
  Agent findings from evidence about human usability.

## Verification

Capture native selection before body access, then package choices before expected
packages. Inspect actual reads and the prototype, introduce the evaluation
phase, and record supplementary reading and the evaluation result. Give the
capable reviewer the contract and raw evidence without the coordinator's
verdict. Judge native selection, each cumulative package, application, and
phase-change reading separately.
